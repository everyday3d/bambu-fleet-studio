# Changelog

All notable changes to **Bambu Lab Fleet Studio** will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.4.1] - 2026-10-24

### Added
- **🛠️ Printer Maintenance Reminders & 1-Click Reset Log (`#42`)**:
  - Keeping up with routine maintenance across multiple printers is easy to forget until a print starts acting up. Each printer now keeps track of its own print hours and reminds you when it's time to **wipe down carbon rods or lubricate linear rails** (every `250h`), **clean and regrease the Z lead screws** (every `500h`), **brush out the extruder gears and check the nozzle** (every `500h`, or clean the optics on an `R1` Laser), and **swap out the carbon air filter** on enclosed printers (every `400h`).
  - Added a small **`🛠️ OK`** or **`🛠️ Due`** badge right inside the Odometer box on each printer card, plus a maintenance tracker inside **✏️ Edit Device** where you can click **✓ Reset** on any item (or **✓ Reset All**) whenever you finish servicing a printer.

## [1.4.0] - 2026-10-24

### Added
- **🔧 Bambu Lab H2C 7-Nozzle Changer & H2D / X2D Dual-Nozzle Support (`#41` — *Untested; Community Feedback Needed!*)**:
  - **H2C Vortek 7-Nozzle Changer Rack**: H2C printer cards now include a dedicated **Vortek 7-Nozzle Changer** section showing the **fixed Left nozzle** alongside all **6 swappable Right induction hotends (`R1`–`R6`)**, including which nozzle is currently mounted, which slots are docked or empty, nozzle sizes (`0.2mm`–`0.8mm`), flow types (`Standard` or `High-Flow`), and print hours.
  - **Dual-Nozzle Temperatures (`L + R`)**: `H2C`, `H2D`, `H2D Pro`, and `X2D` cards now show both **Left (`L`)** and **Right (`R`)** nozzle temperatures and targets side-by-side, and Smart Plug safety locks now wait until **both** nozzles cool below `60°C` before allowing power-off.
  - **🧪 Help Us Test `H2C` & `X2D`**: Since we don't have a physical `H2C` or `X2D` in our shop yet, this support is marked **Beta / Untested**. If you own an `H2C` or `X2D`, please try it out and let us know in **[GitHub Issues](https://github.com/everyday3d/bambu-fleet-studio/issues)** or **[Discussions](https://github.com/everyday3d/bambu-fleet-studio/discussions)** how it looks and if anything needs tweaking!
- **🎉 Now Available in the Official HACS Store**:
  - **Bambu Lab Fleet Studio** has been reviewed and merged into the official **HACS Default Store** (`hacs/default#11882`), with improved camera streaming security and automatic Home Assistant repair alerts if a printer's LAN Access Code ever changes.

## [1.3.4] - 2026-10-24

### Security & HACS Compliance (Frenck Review Round 3 — Fixes #40)

Removed all client-side `&_ts=` appends in `bambu-fleet-cards.js`; both the card stage loop (`_startRtspFrameLoop`) and camera modal polling (`startModalFramePolling`) now consume fresh server-signed URLs from `/api/bambu_fleet_studio/status`.

### Security & HACS Compliance (Frenck Review Round 2 — Fixes #39)

- **Automatic Fahrenheit (`°F`) → Celsius (`°C`) Temperature Normalization (`#12`)**: Fixed an issue on Home Assistant systems configured with Imperial/US units where printer temperature sensors (`nozzle_temperature`, `nozzle_target_temperature`, `bed_temperature`, `bed_target_temperature`, `chamber_temperature`, and `ams_*_temperature`) reported in `°F` (e.g. `73.4°` nozzle / `75.2°` bed / `Target 32.0°` when idle at room temperature, and falsely triggered the `> 60°C` Smart Plug thermal safety lock). All printer and AMS temperature sensors now automatically inspect `attributes.unit_of_measurement` and normalize `°F` values to 3D-printing Celsius (`°C`) with explicit `°C` unit labels.
- **AMS Lite Open-Air Sensor Handling (`#12`)**: Because the Bambu `AMS Lite` is an open-air rotary feeder with no enclosure temperature or humidity sensor (`0°C` / `32.0°F` and `0%` humidity), `AMS Lite` decks now display a clean **`🌬️ Open-Air Rotary`** hardware badge instead of dummy `🌡️ 0°C` / `💧 Idx 1` enclosure chips.

## [1.2.1] - 2026-10-11

### Fixed
- **P2S / X1 / H2 RTSPS Camera Live Feed Fix (`#10`)**: Resolved an issue where RTSPS cameras (`P2S`, `X1C`, `X1E`, `H2D`, `R1`) displayed a black 320×240 placeholder image with a red exclamation mark (`!`) even after enabling `LAN Only Liveview`. Root cause: Home Assistant Core's `/api/camera_proxy_stream/` endpoint invokes `camera._async_camera_image()` directly, bypassing `use_stream_for_stills = True` and returning `BambuLabRtspCamera.camera_image()`'s hardcoded 320×240 red-exclamation fallback instead of decoding the RTSPS stream. RTSPS cameras now use double-buffered offscreen preloading against `/api/camera_proxy/camera.<id>` (which calls `camera.async_camera_image()` → `stream.async_get_image()` and delivers full 1920×1080 HD live frames) in both the card viewport and fullscreen lightbox modal.
- **Zero-Scroll Card Action & Chamber Light Toggle (`#10`)**: Fixed a bug where clicking any button on a printer card (such as toggling the Chamber Light `💡` ON/OFF or switching viewport tabs) caused the dashboard page to scroll back to the top and momentarily blinked live camera streams. Added scroll-container & viewport-card-offset anchoring (`_captureScrollContext` / `_restoreScrollContext`), live camera `<img>` DOM node preservation across `_render()` updates, `type="button"` + `btn.blur()` focus management, and instant optimistic UI toggling on the Chamber Light buttons.
- **Notification Automation Blueprint Compatibility (`#10`)**: Fixed `buildAutomationBlueprint` so non-`mobile_app` notification services (`notify.notify` / `notify.persistent_notification`) omit mobile-only `data.image` fields that caused Home Assistant validation errors.
